# Changelog

## 0.5.0 — CEO Executive Workspace
- NEW dashboard tab (`/ceo-pack`, after Kanban): org chart, live agent activity, task board, and approval center, served by `dashboard/plugin_api.py` (9 read-only GET routes). Every number traces to a registry/roster read; empty states show "No tasks yet", never fabricated activity. Org chart is a generic tree (departments / subordinate agents plug in later, not hardcoded to 8 seats). Task board is read-only — no write routes, so nothing bypasses the tools.
- Persistent task registry with enforced lifecycle: proposed -> approved -> assigned -> running -> blocked/completed -> verified (failed -> running is the retry path). Illegal transitions are refused, `task_key` is idempotent per run, UUID task/run IDs, execution history, dependencies, retry/recovery.
- Task tools return a proper success envelope: the domain state lives under `task_status` / `run_status` and `status` is `"success"`, so `ceo_verify` and the post-tool-call hook verify all 7 handlers clean. `ceo_task_assign` lands the DB row in "assigned" from proposed or approved (the old assign lie is fixed). `ceo_task_list` validates bad input instead of raising.
- Unified CEO delegation provider: each C-Suite seat (CEO, CFO, COO, CTO, CMO, CLO, Chief of Staff, CRO) gets a model route OR a Hermes profile route. Combines Advanced Delegation's model_map and profile_routes into a single backend. Reconciled against the real Advanced Delegation source (`docs/DELEGATION_RECONCILIATION.md`): faithful port of the two real providers merged; reasoning-effort validation matches the host's full list (minimal, low, medium, high, xhigh, max, ultra, none); unknown profile/model fails closed.
- Execution metadata recording: `tasks.record_execution` stores the host-reported route, tokens, cost, duration, API calls, and exit/failure reason (allowlisted fields only; cost is never estimated, unknown stays unknown). The dashboard TaskDetail shows it as "Delegated execution" (requested vs ran-on route).
- Interactive delegation config: hermes ceo delegation config -- curses-based editor for per-seat routes (provider/model with reasoning effort, speed tier, Daybreak; or profile selection). Only `fallback_providers` survives an edit; unknown keys (e.g. a stray `api_key`) are dropped.
- In-chat delegation switching: /ceo delegation [default|ceo_pack] [--now] -- show/switch mode, applies next session or now (rebuilds tools once).
- 7 new task persistence tools: ceo_task_create, ceo_task_status, ceo_task_list, ceo_task_approve, ceo_task_assign, ceo_run_create, ceo_run_status. 21 tools total, 29 slash commands (21 + 7 task commands + /ceo delegation).
- Requires Hermes >=0.22.5 for pluggable delegation providers.
- ceo_orchestrate now creates a persistent run record and can persist tasks to the registry.
- Type 1 approval, honestly stated: tasks with `approval_required=True` are flagged on the assignment and shown pending in the dashboard approval center, and the owner approves in chat — but `ceo_task_assign` does not block an unapproved Type 1 task. A blocking gate (`pre_tool_call`, warn mode first) is design-only and needs Adrian's explicit yes before it is built.
- Catalog art: `assets/ceo-pack-cover-v040.webp` is the install-card thumbnail; the v0.5.0 catalog entry adds `image: https://raw.githubusercontent.com/tradersurfer/ceo-pack/<SHA>/assets/ceo-pack-cover-v040.webp` (see `docs/CATALOG_PR_v050.md`). Note: the file contains JPEG bytes under a `.webp` name — consider renaming to `.jpg` before filing the catalog PR.
- Router fixes from the Nov 19 live ladder (mobile + laptop, 33/35): signing a document now infers `outside_authority` as well as `legal_or_financial` — the sign pattern allows intervening words ("sign the vendor NDA") and `_RISK_CUES` gains an `outside_authority` cue (signing / countersigning / acting on behalf of). People verbs now route: "Fire the shift lead" goes to Chief of Staff ("fire", "terminate", "lay off", "demote", "discipline", "dismiss" plus the "shift lead" phrase as the tie-breaker against CRO's "lead"). Guards verified: terminating a vendor contract still goes to CLO, dismissing a customer complaint still goes to CRO, "review the proposal for new laptops" still goes to CRO.
- Live dashboard (Phase 2 continuation): seat nodes now carry `last_activity` — the seat's latest registry activity (newest of its task `updated_at` values and history events on its tasks), `null` when the seat has no recorded activity, so the UI shows "unknown" and never invents one. The frontend polls every 30s (no push channel — the plugin API is GET-only by design); a seat active in the last 2 minutes shows a pulsing live dot, and tasks/seats/feed lines that moved since the last poll flash once for 5s. Roster endpoint never fails on a missing registry — seats fall back to unknown.
- Dashboard writes (first slice): four POST routes (`/tasks`, `/tasks/{id}/approve`, `/tasks/{id}/reject`, `/tasks/{id}/assign`) that call the same `tasks.py` functions the chat tools call — same lifecycle + permission checks, same registry, same history audit (actor recorded as the owner acting from the dashboard). The host authenticates every `/api/` call, so the caller is an authenticated Hermes user. New terminal status `rejected`, reachable only from `proposed`. `_connect` now sets WAL + a 10s busy timeout (the agent and web-server processes both write the DB); a contended write surfaces as 503. The UI gains Approve/Reject buttons on pending approvals, an Assign control on the task detail, and a Create task form on the board — each disables while its request is in flight and shows the server's detail string on failure.
- Tests: 310 total (297 + 13 new dashboard-write tests in tests/test_v050_dashboard.py), all passing, demo rc=0, Nous validator 15/15. One pre-existing warning remains: private core imports in the delegation files (catalog rule 9) — see `docs/DELEGATION_RECONCILIATION.md` §7 for the per-import seam analysis; the one replaceable import (the host's private reasoning-effort picker) was replaced in Phase 4.
- Cleanup: dead `tools_task_handlers.py` and build scaffolding (`__init_new.py`, `write_init_part1-7.py`, `ceo-pack-audit.patch`) removed.

## 0.4.0
- FIXED router (Hermes live test P0): whole-word matching with per-seat priority, matched terms, also-consult, and confidence. "Review the supplier contract" now routes to CLO, "Fix the checkout bug" to CTO, "Close the books" / "Reconcile books" to CFO. "Review the proposal for new laptops" no longer routes to COO. Unmatched tasks go to CEO at low confidence instead of silently claiming a domain match.
- FIXED verify / assign status mismatch (Hermes live test P0): every real tool result now verifies clean with default expected fields per tool. ceo_assign, ceo_brief, ceo_route, q4_closeout_checklist, ceo_orchestrate, and ceo_choose_model all return status success; gated decision logs return needs_approval and stop for the owner. A validated envelope is still not a completion.
- FIXED Ling 3.1: bare `inclusionai/ling-3.1-flash` is PAID ($0.075 in / $0.225 out per 1M). Free worker 2 is now `inclusionai/ling-3.1-flash:free` in models.py, docs/MODELS.md, and skills/model-selection.
- Handlers never raise: non-string / null / wrong-type input returns a JSON error, never an AttributeError. Every handler now refuses credential-like input, not just ceo_tool_call.
- Secret scanner hardened: squashed-key matching (api_key, API-KEY, zero-width splits), fail-closed past depth 20, JSON-string arguments scanned, secret-as-key redacted, plus Stripe, Bearer, Google, Hugging Face, npm, SendGrid, and embedded-credential URL patterns.
- Type 1 from wording: pay, send to a client, delete, fire, file taxes, wire funds, publish, rotate a password, and set pricing raise a call to Type 1. Misspelled or non-dict risk flags are refused instead of silently staying Type 2. A decision log cannot ungate Type 1 wording. Plans mark the call step approval-required for risky goals and carry a deterministic run_id.
- Q4 trigger now catches "taxes" / "taxation" ("File our 2026 taxes" adds the checklist step). Q4 year must be a four-digit year 2000-2100.
- NEW seat aliases (config): rename any seat for display, e.g. COO to Poseidon, CEO to Billy. Canonical seats never change; logs show Alias (Canonical); duplicate aliases are refused.
- NEW head CEO config: head_seat (default CEO) and optional head_profile. The human owner is still the final Type 1 gate.
- NEW capability check (orchestration API): per-seat checklists, missing items listed, install-missing returns an owner-gated install plan (nothing installs inside the plugin), declining leaves a name-only binding flagged in plan and log.
- NEW opt-in business-data reading (orchestration API): ephemeral, chat-scoped, explicit field list plus purpose plus expiry, every read audited, instant revoke, fresh opt-in required for any future read. Fictional-data test only.
- NEW slash commands (shortcuts to existing tools, no new tools): /brief, /assign, /verify, /log, /decision, /route, /models, /weekly-pulse, /closeout. Existing /ceo, /q4, /orchestrate unchanged.
- Post-tool-call hook skips meta tools (ceo_tool_call, ceo_verify) and now also verifies q4_closeout_checklist.
- Scrubbed personal and business names from SUBMISSION.md. This version is not pushed to Nous.
- Tests: 38 new v0.4.0 regression tests in tests/test_v040.py, plus the 34 v0.3.0 tests and the demo, all passing.
- v0.4.0 additions (design answers, 2026-11-12): generalized closeout — ceo_closeout_checklist covers Q1-Q4 + monthly (q4_closeout_checklist stays as an alias); new tools ceo_daily_check (daily/EOD), ceo_performance_check (people = Type 1, owner approval), ceo_status_check (reports only what it is given, never invents a status), ceo_roster (install flow + pinned CEO Dashboard data). 14 tools, 21 slash commands. Seat bindings now carry all three display fields — name + avatar + SOUL — display-only. First industry suite after v0.4.0: SaaS.
- Research round (2026-11-14, ranked top-20 business tasks AI agent users actually ask for): router expanded from 19 domains / ~10 terms per seat to 37 domains and roughly 3x the terms. Writing/email drafting -> Chief of Staff, coding/debugging -> CTO, content/social -> CMO, deals/proposals/support -> CRO, forecasting/runway/board -> CFO, inbox/calendar/documents/monitoring -> COO, fundraising/investors -> CEO. Multi-term scoring already in place means "close the sales deal, contract attached" routes CRO (3 terms) over CLO (1), and "close the quarter" / "close Q4" route CFO via the new quarter/Q1-Q4 terms. One-liner limits are by design: closing a complex deal, final contract sign-off, and hire/no-hire still need the brief first.
- Framework catalog path fixed (2026-11-13): all 20 references to `core/frameworks/catalog.js` (a path from the separate ceo-agent project) now point at `engines/framework-catalog.js` in this repo.
- Ling price wording corrected: models.py and docs/MODELS.md no longer quote a specific paid price for the bare Ling ID (it varies by provider) — the rule stays "bare = paid, use :free".
- Tests: 15 new router regression tests in tests/test_v041_router.py (104 total), all passing, 20/20 back-to-back, Nous validator 15/15, no warnings.

## 0.3.0
- NEW `ceo_verify` tool: the Verify step of Brief -> Route -> Plan -> Assign -> Call -> Verify -> Log now exists in code. A call that started is not a call that completed.
- Secret scanning covers nested keys AND values (JWTs, `sb_secret_`, `sk-`, GitHub, AWS, Slack, private-key blocks). Errors name the path, never the value.

- Type 1 now covers security, people, regulatory, reputation, and outside-authority, matching the docs.
- Plan no longer gates every call by default (Type 1 stops, Type 2 proceeds) and only adds the Q4 checklist for Q4 / year-end goals.
- JSON-string arguments are parsed instead of rejected.
